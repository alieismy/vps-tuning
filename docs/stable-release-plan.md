# 首次正式版迁移与收敛方案

日期：2026-11-24。状态：用户已批准按修订方案执行；2026-11-26 正式候选工程/隔离验证已完成并[冻结](releases/v0.2.0.md)，VPS 变更与公开发布仍须单独授权。用户已决定撤销 T1–T10 旧实机发布门槛，并确认除 Oracle/AWS 外现网重新安装 rc.4，包含 apply 与重启后 verify。已生效的验收修订与部署事实由[验证说明](validation.md#stable-release-gates)单一维护。

推荐以当前 rc.5 修复为实现基线，形成 `v0.2.0` 首次正式版；现网 rc.4 直接迁入正式候选，不把先升级 rc.5 作为前提。采用固定来源与目标、先恢复基线再应用目标的迁移，保留两次人工重启。优先完成真实需要的版本、带宽、配置保留及恢复契约；原地接管和版本解耦留待独立设计。

## 依据与范围

- 本仓库评估基线：master `aeeb0d50a2eebaa6e407e8f17aa78c6f577778d4`；公开 rc.5 与当前主线运行资产未变。rc.6 工作树以此为起点；既有 rc.5 工程证据见[rc.5 发布验证](validation.md#rc5-release-validation)。
- 手册盘点来源：`alieismy/vps-doc` 的本地修订 `2afd5dc421d3d81cf8f8e0d4dc7eccdce5466e3d`，`providers/{vmrack,vmiss,yunyoo,eugamehost,dmit}` 的部署手册资源表及适用边界。方案仅保留资源和操作差异，不复制地址、域名、凭据或完整业务配置。DMIT 资源采用用户本轮补充；手册尚未回写。
- 核心能力保持 17 项 sysctl、资源感知 BDP、BBR + fq、既有文件所有权、预算与恢复约束。持久配置平台范围见[平台支持](platform-support.md)；独立诊断/测量按其实际能力前提。
- 当前九台手册均以 Debian 13/amd64 为目标。Oracle/AWS 不参加本工作包；Ubuntu/ARM64 产品支持继续由明确的隔离客体证据支撑，不宣称已在用户这些云主机验收。
- 不包含重装操作系统、改代理业务、永久 HTB、通用 UDP 调优、扩展发行版、跨 OS/profile 迁移、全面性能研究或九台强制升级。

## 迁移候选比较

| 方案 | 实现及恢复方式 | 开发与运行成本 | 证据与主要风险 | 结论 |
| --- | --- | --- | --- | --- |
| A 固定版本恢复后重应用 | 复用 checkpoint、来源 rollback、两个 boot gate、目标 apply/verify；在此基础上补正式版本格式、参数冻结与互斥 | 开发变化相对集中；每台需维护窗口、两次重启，脚本创建的 swap 可能需移除重建 | 已有迁移路径和 VM 生命周期可复用，但不能证明新版本新增分支；来源 rc.4 的恢复失败仍可能需要人工接续 | 首次正式版推荐 |
| B 原地接管受管状态 | 保留运行配置/原快照，事务性改写版本归属、文件摘要和运行资产 | 预期少重启、少业务中断；须新建跨版本文件/状态转换及降级事务 | rc.4→rc.5 含恢复实现变化，不能只改 script_version；中断时旧、新版本谁能回滚必须重新证明 | 暂不用于首次正式版 |
| C 程序版本与配置修订解耦 | 入口可升级，状态显式标识配置契约/兼容集合，迁移按修订执行 | 长期可减少仅工具更新造成的迁移；首次需更广的状态、选择器、兼容及发布设计 | schema 相同不等于语义兼容；还需解决已发布旧脚本的状态解释 | 单独后续方案，不作为首次发布前置 |

方案 A 的推荐置信度为中高：改动集中且复用已有恢复机制；代价是维护中断和来源恢复风险。若只读盘点发现原值不完整、rc.4 无法可靠回滚、维护窗口不可接受或存在无法说明的外部归属，应停止该主机迁移，保留正常运行的 rc.4；不自动转向 B、猜恢复值或重装系统。大量同契约维护更新反复触发重启时，才重新评估 C 的收益。

## 推荐迁移契约

### 版本和平台

1. 首次正式版直接来源明确限定 `0.2.0-rc.4`、`0.2.0-rc.5`；若为本工作包发布了新的固定 RC，再通过显式白名单和测试纳入。更早版本维持各自固定工具和历史恢复路径，不推导出任意旧版直达支持。
2. 源/目标版本解析允许明确的正式版和 RC 格式，但执行仅接受本次批准并测试的迁移边。放宽正则不等于放宽来源白名单；入口、profile、迁移器、清单和 checkpoint 必须绑定固定版本及摘要。
3. 首次迁移必需范围以现网 Debian 13/x86_64 为中心，保留现有 Debian 12 迁移范围并验证兼容；配置输入拟对齐已有 1–10000 Mbps 契约，以覆盖可能按 5000 Mbps 配置的主机。套餐上限不等于 state 中实际 port，须先盘点。仅同 OS/架构/profile 且当前资源仍匹配的来源。Ubuntu 迁移和 ARM64 迁移不以新装支持为由强制补齐，也不移除已有 ARM64 路径；先核对来源资产和已有兼容范围，若纳入正式迁移承诺，须补相应验证，否则明确未验收边界。Ubuntu/ARM64 的新装支持与七组生命周期保持，不将迁移全平台矩阵列为首次发布默认前置。
4. 不强迫用户通过 rc.5 再到正式版。主程序的后续正式版更新继续采用明确的来源/目标兼容表；本次只证明首次迁移边，不提前承诺尚不存在的 0.2.1 可无重启升级或任意降级。

### 配置和恢复基线

- 来源必须是有效、完整、通过旧版核验的状态，所有权与原始恢复值可校验，且没有活动重配置、HTB 或另一迁移。重装后以本次部署状态为准，不能套用旧 rc.2 的 replacement/historical 归档。
- 在任何来源回滚前，持久保存经过校验的来源状态、队列/厂商文件恢复材料、必要的固定来源资产及配置意图。材料置于受管清理树之外，root-only，摘要核对；留存本身不授权直接拷回旧 state。
- 显式冻结套餐带宽、目标 RTT、buffer 的 auto/explicit 意图与适用值，以及脚本 swap 的启用/大小策略。目标有效差异在准备阶段展示并绑定；不把来源 `auto-clamped` 的结果误转成永久显式值，也不静默采用目标默认值覆盖用户选择。
- 来源未保存足够信息以重建某项意图时，准备阶段暂停并让操作者确认可验证的目标值；该确认记录在 checkpoint。公开 rc.5 迁移器只显式传递 port；本地 rc.6 的新增字段及校验见[实施契约](stable-migration-design.md)，须通过新增验证后才作发布承诺。
- 配置只从经验证的来源字段及明确确认值重建，不整体继承调用 shell 的环境。现有 state 的 `swap.created_by_script=false` 既可能表示用户关闭创建，也可能表示已有外部 swap 或文件系统不适用，不能推断成 `ENABLE_SWAP=0`；属于这类不明输入时仅补充该项确认，不要求所有默认参数逐项重填。配置选项与服务验收选项分开：目标 apply 前后采用适用的配置验证，第二次重启后再显式执行严格代理验收；不能把 `REQUIRE_PROXY_SERVICE=1` 或显式服务列表无差别传入全部阶段，令尚待重启生效的 NOFILE 被误判为 apply 失败。
- 不迁移预算 ledger、代理数据库、vps-kit 流量任务或防火墙归属。它们保留各自路径与生命周期；DVT 的回滚不得删除这些材料。已知外部写入同一状态目录时停止并协调，不以“拥有 root”绕过归属。

### 执行和故障边界

准备固定资产与恢复材料 → 旧版核验及目标只读预检 → 写入 PREPARED → 来源固定脚本恢复基线 → 第一次人工重启 → 核验恢复基线与目标预检 → 目标 apply → 第二次人工重启 → 目标严格验证与真实客户端验收 → 完成受管迁移及入口切换。

这是目标控制流，不是可立即执行的命令。`update` 保持只读；目标安装不提前覆盖唯一可用来源入口；操作者决定维护窗口和重启。checkpoint 完成、入口版本一致和客户端业务通过分别记录，不能用任一项代替另外两项。

- 对同一主机的迁移建立独占控制，不仅锁单个 checkpoint；阻止两个不同 checkpoint 争用同一受管状态。锁只覆盖一次命令执行，不宣称进程锁能跨重启：未完成任务的归属须由持久 checkpoint/活动任务记录确认，异常后核对并接续，而非另建任务绕过。与 profile 原有锁协调，避免父子调用死锁。该保证限定迁移器之间，不宣称能阻止旧脚本或任意 root 操作；维护窗口内其他受管写操作应串行。具体表示和锁作用域由详细设计及双实例测试确定，不建立通用跨工具调度框架。
- 来源 rollback 失败时保留来源资产、归档和 checkpoint，停止在恢复阶段；目标 apply 失败时使用目标版本自己的恢复路径，检查已恢复的基线后再允许接续。不得用目标脚本卸载旧来源，也不得通过手改 phase/state 宣告成功。
- 对基线恢复重试、APPLIED 残留、普通清理中断、swapoff 失败和状态漂移逐项验证。启动持久性检查覆盖 fq helper 的 enable/执行状态与实际队列；不能只凭文件存在证明下次启动有效。
- 回到原 rc.4 服务状态不等于复制备份 state：仅在目标已可靠退出、基线已核验且另行确认后，按固定来源资产重新应用已记录的来源配置并验证。迁移后的自动降级不在本次承诺内；控制台和业务备份是异常恢复前提。

## 收敛工作包

下列为已批准的本地实施顺序及完成标准。文档与代码实施已启动，运维及公开发布仍分别授权；发布验收以[验证说明 G1–G6](validation.md#stable-release-gates)为唯一门禁来源。

| 工作项 | 有边界的交付 | 完成判据及责任 |
| --- | --- | --- |
| W0 基线与范围 | 记录九台用户确认的 rc.4 基线，退役 T1–T10；只读盘点实际 OS/架构、版本/profile、port、RTT/buffer、swap、原值完整性、qdisc、服务版本及恢复入口 | 文档已更新；目标机盘点由获授权操作者提供。重装未回传的字段保持待采集；不要求先升级 |
| W1 正式迁移最小设计与实现 | 上述必要来源/平台/输入契约、配置冻结、基线材料、迁移互斥和明确接续；以 rc.5 已有修复为基础 | 实施者交付明确支持边、实际函数正反例、准确退出码及中断恢复证据；既有 schema 是否需扩展由具体设计决定，不机械升级全部 schema |
| W2 正式候选工程验证 | 现有完整静态/root/PTY/原生 tc/ShellCheck 和七组新装平台；另用真实固定 rc.4/rc.5 来源资产验证到目标的隔离迁移与真实重启。5000 Mbps 输入、配置保留和中断接续按改动补证 | 不以替身迁移或新装生命周期代替真实迁移；不要求所有来源×平台×资源全排列。迁移修改可能不触发当前平台 workflow 路径过滤，须显式安排相关运行 |
| W3 代表性灰度 | 先选一台恢复条件清楚、业务基线稳定的现网主机；其余是否加入取决于隔离测试未覆盖、且会改变结论的真实拓扑或业务差异 | 每台维护窗口单独授权；迁移/重启/严格服务/管理入口及客户端连接、传输、重连通过后才考虑扩大。没有固定 2–3 台或全部资源档灰度要求，结果绑定冻结候选及资产 |
| W4 发布闭环 | 冻结正式版本、双语说明、支持/迁移/已知限制、固定资产、准确提交 CI 和公开下载回验 | 用户作发布决定；发布者交付完整固定制品。没有用户授权不创建 tag/Release，不改 rc.5 资产 |
| W5 按需推广 | 将余下主机作为正式版发布后的独立维护选择 | 不把九台全部迁移作为发布前提，不因发布自动升级，也不为统一版本承担无收益的业务中断 |

W1/W2 在可丢弃环境中迭代。需要业务机试用而实现尚未冻结时，采用唯一版本的候选（如另行决定的下一 RC），每个版本绑定不可变资产；只有试点机参与，不要求其余 rc.4 主机跟随。当前安装器拒绝同版本不同清单，迁移入口也拒绝同版本重复迁移，因此不能在已安装候选的主机上仅更新摘要就覆盖修复。

正式版本号只在实现冻结后用于最终制品验证。发布前的本地 bundle 路径须区分：`install.sh --source-dir` 是安装能力，常规 `update --target` 仍依赖已公开目标 Release；本地目标总控的 `migrate prepare` 与来源资产解析路径须单独验证，不能把离线安装成功当作在线更新链成功。最终正式目标需使用自身版本和摘要完成 G2/G3 及首台 G4 的适用验证，再公开同一字节并回验在线路径。若最终候选已在主机产生受管状态后仍需修改，应保留该版本完整资产、停止发布，先按已验证恢复路径退出，再采用新的唯一候选；不覆盖同版目录、不把 state 改版本。该代价是延后使用正式版本号和缩小最终试点的理由。若先用了独立 RC，最终还需验证 RC→正式版，不只改标签借用结果。

代表机候选池包括 VMISS Basic、DMIT、VMRack、YunYoo 和 EUGameHost，不预定必须迁移的名单。按业务基线、恢复条件、维护影响与实际 qdisc 选首台；存在未解释故障的主机不作首台。2C2G、5000 Mbps 输入与单/双栈先复用或补充隔离证据，只有仍存在实质云平台或业务差异时才增加相应实机。5000 Mbps 套餐主机以 state 的实际 port 制定迁移，不借迁移顺带改套餐参数；高输入验证不要求公网满速。

对单/双栈，验证已有正常使用的地址族，不临时添加 IPv6。收敛工作不改代理 CN 规则、AI 出口、REALITY Target 或链式代理；业务异常须先区分原有线路/应用问题与候选引入的问题。正式候选的正常使用观察窗口在灰度前固定，覆盖重启后检查、实际常用业务及约定并发；不靠任意天数或一次成功连接宣称长期稳定。

## 暂缓事项与重新纳入条件

- 原地接管、版本解耦、全历史版本通用迁移：本次窄迁移无法满足明确维护成本目标时再评估。
- 低速窗口顺序效应、policer 判据和性能研究：遵循[项目备忘](project-memo.md)既定触发条件；保留无效样本门禁，不通过放宽容差获取发布通过。
- 外部 root 晚到写入：正式迁移采用树外归档和独占协调降低影响，仍不承诺抵御任意外部 root 改写。若串行受支持流程也可复现材料丢失，转为本工作包必须修复的问题。
- Ubuntu 迁移扩展、未覆盖的 ARM64 迁移及云厂商实机、Oracle/AWS：发生真实使用需求或拟作相应迁移/业务承诺时纳入；保留已有新装支持及已实现兼容行为，不能用当前九台替代其他平台业务证据。
- 2/5/10 Gbps 公网吞吐及业务提升：只有明确性能问题、预算和授权才开启，不阻塞配置管理正式版。

已批准采用本方案；开发阶段使用 rc.6，正式目标 0.2.0 已完成工程/隔离验证并冻结，灰度维护授权与实机/发布门禁仍待完成。方案不承诺工期，实际工作量取决于只读盘点结果和迁移恢复测试，不以“重装过 rc.4”推定恢复材料一定完整。
