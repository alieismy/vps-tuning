# v0.2.0-rc.4 预发行说明

状态：候选，待本地与 Linux CI 验证、合并、固定 tag 和公开资产回验；用户已于 2026-10-13（Asia/Singapore）授权验证通过后发布 Pre-release，不设为 Latest。

## 变更范围

- 修正 rc.3 评审发现的版本冲突引导：当入口版本与可读取的受管状态版本不同时，主页提示原因，将 1–6、9 和高级页 HTB 标为不可用。默认项改为 7（本地能力诊断）；8（只读联网升级检查）仍需明确选择。历史 VERIFIED 记录在异版情况下使用提示色，避免与当前版本可用性混淆。
- 菜单不自动执行 update、迁移或配置写入；显式 CLI 行为、底层版本/所有权/完整性门禁不变。只读诊断仍需要原有 Python 和本地配套资产，缺失时按原契约拒绝，不自动下载安装。
- 在现有 controller 回归之外增加 Linux PTY（伪终端）测试，通过真实终端执行 main、输入、确认、菜单分派与退出路径；系统操作用测试替身隔离。该证据不等同于实际终端字体渲染或 VPS 业务验收。
- 总控、九份 profile、安装器、迁移器和 TCP 基线恢复工具同步到 `0.2.0-rc.4`；只读 update-preflight 和迁移器增加 `0.2.0-rc.3` 来源，保留 `0.2.0-rc.2` 和 `0.1.0-rc.1`–`rc.19`；`0.2.0-rc.1` 来源仍被拒绝。
- 离线 probe 校准器的同格式白名单增加 rc.4，保留旧版本。独立测量、预算等工具内部版本与 schema 不变。

17 项受管 sysctl、资源感知 BDP 缓冲、默认 `BBR + fq`、非持久 HTB、managed-state schema 4、benchmark schema 3、预算 ledger 和两次重启 checkpoint 门禁全部保持。没有性能收益主张。

## 采用与迁移边界

菜单是可选的人工作业入口；精确操作与自动化继续使用显式 CLI。五台已经验收的 rc.2 主机保持原版本；不建议已正常运行的 rc.2/rc.3 主机仅为菜单修正升级。

迁移仍需 prepare、来源 rollback、第一次重启、目标 apply、第二次重启和 verify。迁移器仅接受 Debian 12/13 profile、100–1000 Mbps 端口；没有扩展到 Ubuntu 或其他端口范围。版本在白名单中不代表通过其余门禁。

TCP 基线恢复归档只能交给同工具版本迁移器；旧 rc.2/rc.3 工具建立的归档应先完成各自目标版本，再迁移到 rc.4。不得修改归档版本或用新值冒充历史原值。详见[迁移指南](../migration.md)及[恢复工具说明](../tcp-baseline-recovery.md)。
