# v0.2.0-rc.5 修复候选

状态为本地未发布候选，2026-11-23。本次实施依据[已自检评审](../proxy-vps-fit-review-2026-11-22.md)，目标为 Debian 13、Ubuntu 24.04 主用、Debian 12 兼容以及 100–2000 Mbps 代理 VPS。

## 修复范围

- 严格服务核验要求显式 unit 加载且活动，主进程限额可读。要求代理业务运行时，x-ui 必须有可识别的直接 Xray 子进程。默认安装前核验继续适用。
- 当前默认路由接口为空时，队列验证报告无法核验。adaptive 内存封顶后仍覆盖目标 BDP 时，告警正确说明已覆盖。
- 首次 apply 在发布文件前登记预期哈希，回滚继续核对内容。清理前检查发现状态目录中的未知文件、账本或子目录时保留现场，提示先迁出数据后重试。
- 新账本及迁移 checkpoint 拒绝放在受管状态树中。已有旧账本仍可查询和结算，应在完整清理前迁到独立目录并核对。
- 迁移接续遇到 APPLIED 残留时在第二次重启前停下，保留现场并给出恢复入口。同版只改变套餐带宽时，apply 提示 reconfigure。
- benchmark 实际应用解析后的软件速率限制，父子工具按硬超时、终止宽限和每流余量一致预留。非零预热或无法确定完整发送量时保守结算，并覆盖已知发送字节。计数器使用 parent 区分多队列叶子并识别十六进制 parent。
- 临时 HTB 看护遇到所有者在发信号前退出时，继续执行已有恢复路径。
- Xray socket 诊断标明默认配置路径与活动来源未核验。fq 开机持久性及迁移并发仍按评审的证据边界处理。

候选沿用 17 项 sysctl、资源感知 BDP 缓冲和默认 BBR + fq。跨版本迁移目标为 rc.5，来源增加 rc.4，仍受现有 Debian profile、100–1000 Mbps 及状态完整性限制。Ubuntu 和 2000 Mbps 新安装支持不能视为迁移承诺。TCP 基线恢复工具与迁移器同为 rc.5，计划、receipt 和恢复来源记录必须明确绑定 rc.5。已批准给 rc.4 的归档继续使用其固定 rc.4 流程。

## 2026-11-23 实施自检

- **Major，恢复目标版本语义已修正。** 上一轮把 rc.4 恢复归档直接用于 rc.5 的解释不成立。target_version 属于逐台批准的控制字段，现已恢复同版校验，加入 rc.4 拒绝与 rc.5 正例。
- **Major，显式服务列表漏检已修正。** 旧进程替换吞掉非法 unit 的解析退出码，曾出现 stderr 报错而函数返回0。现先完整解析并检查结果，空白列表及多行输入也明确拒绝。
- **Major，旧 HTB 实验机制记录已补齐。** 同速软件节拍可能影响突发、CPU 和重传，overlimits 有值也不能排除这些混杂。阶段与会话记录经校验的子 benchmark 软件限速元数据。候选与旧无软件节拍归档不宜直接作因果比较。
- **Minor，文档版本范围已修正。** 高级测量页当前示例和预算契约明确适用于 rc.5 候选，历史附录保留固定版本。
- **Major，离线校准报告版本兼容遗漏已修正。** 同格式 rc.5 证据曾被来源版本白名单拒绝，先用实际分析器复现失败，再补入 rc.5；既有来源版本继续支持，未评审 rc.6 仍拒绝。

**条件风险仍开放。** 清理前检查通过后，若旧工具或其他 root 进程再写入，当前实现保留新内容，但可能已删除 state.json 和队列快照。离线注入复现了目录删除失败、账本保留、部分事务材料已删。新工具拒绝在该目录创建账本，主程序锁约束同一主程序操作；旧工具或其他 root 写入仍需独立协调。本轮收窄保留现场的声明并改进失败提示，未增加另一套清理备份事务。完整并发恢复尚无验收结论。
