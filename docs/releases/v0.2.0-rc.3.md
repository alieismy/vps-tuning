## 变更范围

### 交互界面

按[交互界面详细设计](../interactive-cli-design.md)重做无 action 时的 `dvt` 菜单，只改总控的表现层：

- 单屏框式主页：分组双语菜单，每项标注副作用（只读、写入、重启、联网、流量、子菜单）；框外显示主机、档位、受管记录和运行值。主页事实不联网、不写文件、不要求 root，外部字符串经白名单校验后才显示。
- 默认项按受管记录选择首个只读动作：无状态时为安全引导，`APPLIED` 为验证，其他状态为查看状态；非 root 或平台不支持时只有能力诊断可用，其他项显示“不可用”并在选中时说明原因。
- 无效输入重新提示，第 3 次仍无效时以原文案和退出码 2 结束；读到 EOF 或选 0 时不执行任何操作并退出 0。
- 菜单路径的 `rollback` 新增确认；写入和回滚确认默认 N，EOF 视为否。菜单执行的动作结束后显示结果页（退出码、含义、下一步），退出码不变。
- `probe`、`benchmark` 不再从主菜单分派，与 `measure`、`htb-sweep`、`report`、`migrate`、`recover` 一起列在“高级与测量”页的命令参考中。设计中的“测量预览”菜单项经评估不保留，改为命令参考行 `dvt measure --rate-cap N --plan-only`。
- 无终端且未指定 action 时，保留原第一行错误，再给出 `ssh -t` 和自动化示例，退出码仍为 2。
- 支持 `NO_COLOR`（非空即禁用颜色）和 `DVT_ASCII=1`（ASCII 框线）；`TERM` 为空、`dumb` 或 `linux` 以及终端窄于 66 列时改用开放布局。只使用 SGR 颜色序列，不清屏、不移动光标。

CLI 语法、action 集合和退出码定义不变；显式 action 在非终端下的检测结果与执行计划文本不变。唯一的退出码变化在交互提问处：菜单、端口带宽和确认提问读到 EOF 时一律退出 0，旧版菜单路径和端口带宽提问在这种情况下由 `errexit` 以 1 结束；端口带宽输入无效时也从立即以 2 结束改为最多 3 次重新提示（设计 §9、§10.2）。profile 及配套脚本的输出不变（是否统一着色仍为延期事项）。

### 版本与迁移

- 总控、九份 profile、安装器、迁移器和 TCP 基线恢复工具的版本改为 `0.2.0-rc.3`。预算工具、`tcpquality-evidence.sh` 和测量工具保留原内部版本，由清单固定字节。
- 只读 update-preflight 额外接受 `0.2.0-rc.2` 的 schema 4 状态；普通动作仍要求状态版本等于当前版本，`0.2.0-rc.1` 状态仍被拒绝。
- 迁移器接受 `0.1.0-rc.1`–`rc.19` 和 `0.2.0-rc.2` 来源，目标为 `0.2.0-rc.3`。profile ID 仍限 Debian 12/13，端口仍限 100–1000 Mbps，所以 Ubuntu 24.04 主机和端口超出该范围的 rc.2 主机不能使用本迁移器；这类主机的处理需要另行决策。
- TCP 基线恢复工具生成的归档只被同版本迁移器接受。已用 rc.2 工具建立恢复归档、但尚未完成迁移的主机，先用 v0.2.0-rc.2 完成迁移，再执行 rc.2 → rc.3。
- 离线 probe 校准器增加 `0.2.0-rc.3` 版本标识的同格式兼容。

17 项受管 sysctl、资源感知 BDP 缓冲、默认 `BBR + fq`、非持久 HTB、managed-state schema 4、benchmark schema 3、预算 ledger 和迁移 checkpoint 门禁保持不变。

## 升级影响

总控、profile 与受管状态的版本绑定在一起（见设计 §10.3）。已受管的 rc.2 主机要在新界面下执行 `status`、`apply` 等受管动作，必须先完成 rc.2 → rc.3 迁移：prepare、旧版 rollback、两次重启门禁、目标 apply 和 verify。界面改版本身不改变调优结果，没有性能收益主张。
